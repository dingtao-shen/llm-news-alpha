# FNSPID 日期 / 时间戳校验结论（模块 2 任务 4，2026-10-23）

## 证据

1. **直接抓取不可行**：benzinga.com 与 nasdaq.com 对数据中心 IP 一律返回 Cloudflare 403。改用 Wayback 快照，400 条样本中 74 条有快照、45 条抓到页面；
   nasdaq.com 的归档页是 JS 壳，只有 2023 年的少数页面能解析出发布时间（见 `tz_check.csv`）。
2. **Benzinga 有时刻记录：FNSPID 时间戳 = 真实 UTC − 8 小时，13/13 条完全一致**（2016–2020，冬夏季都是 8 小时）。
   例：FNSPID `2019-11-13 07:50:38` vs 页面 `2019-11-13T15:50:38Z`。数据卡标注的 "UTC" 不成立：按 UTC 解读会把新闻提前 8 小时，
   使盘中发布的新闻被算进当天开盘（前视偏差）。按美东解读也不对（差 3–4 小时）。
3. **nasdaq.com 2023 年"有时刻"的 26,623 行全部标注 2023-12-16**（数据集最后一天），且解析出的 2 个页面真实发布于 2023-12-18：
   这些时间戳是抓取时间不是发布时间，且日期可能早于真实发布。
4. **2023-11-30 至 2023-12-16 的 nasdaq.com 行量异常**：2023 年 1–10 月每天中位数 1,206 行 / 722 篇，这 13 天每天 15,000–54,000 行、每篇挂 14 个 ticker，
   12-17 之后几乎为零。这是最后一次抓取把一批文章打上抓取期日期造成的，日期不可信（2022 年末没有这种尖峰）。
5. **URL 自带日期的全量检查**（不依赖抓取）：nasdaq.com 2015–2021 的 900,006 行 URL 末尾带日期，99.1% 与 FNSPID 日期相同，
   0.9%（仅 2019–2021）URL 日期比 FNSPID 晚一天（FNSPID 偏早，前视风险方向）；Benzinga URL 年月与 FNSPID 一致 99.99%，
   不一致的 5% 是 FNSPID 日期晚于 URL 月份（滞后，安全）。
6. Benzinga 仅日期记录只解析出 1 页（同日，07:00 ET 发布）；nasdaq.com 仅日期记录 0 页。**仅日期记录的发布时刻分布仍然未知**，
   无法判断"16:00 截止 + 收盘成交"能否吃到隔夜收益。

## 规则（写入 news/build_clean.py，开关 DATE_FIXES）

| 来源 / 情况 | 规则 | 影响（news_clean 行数） |
| --- | --- | --- |
| Benzinga 有时刻 | 时间戳 + 8 小时后再按 UTC 转美东；保留 second 精度 | 2,321 行中约一半特征日推后 1–4 个交易日 |
| nasdaq.com 有时刻（全部为 2023-12-16） | 剔除 | 96 行 |
| nasdaq.com 2023-11-30 至 2023-12-16 的全部行 | 剔除（抓取期打标） | 约 1,500 行 |
| nasdaq.com URL 日期晚于 FNSPID 日期 | 日期取 URL 日期（只推后，不提前） | 1,538 行 |
| 其他 | 不变 | |

对结果的预期影响：2023 年测试样本减少约 3%，有时刻子集的特征日整体推后；表 A、多空表需重算（聚合 → Ridge → 表 A → 多空，约 25 分钟）。
